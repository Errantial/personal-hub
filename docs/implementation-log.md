## 2026-11-10 - Edge hardening: per-client limits, compression, caching and security headers

Read-only checks of the live site found four gaps. The API's rate limits were keyed on the reverse proxy's loopback address, so all clients shared one bucket: ten failed sign-ins from anywhere would block the owner's sign-in for fifteen minutes, and a first request from a new address already showed other clients' usage in `x-ratelimit-remaining`. Static files and API JSON were sent uncompressed (656 kB entry script, about 1.1 MB for the first precache). No security headers were set. A missing `/assets/…` path answered 200 with the app shell. The live Caddyfile also turned out to hold other sites' blocks, which `provision.sh` would have overwritten.

Changes:

- API: `TRUST_PROXY` (`loopback` by default in production, `off` elsewhere) makes Fastify take the client address from `X-Forwarded-For` only when the peer is loopback, so every limit is per client and a direct caller cannot choose its key. A limited request now answers 429 `RATE_LIMITED` with `Retry-After` instead of `INVALID_REQUEST`, and the web client explains it. API responses add `X-Content-Type-Options: nosniff`.
- Caddy site block: compression, HSTS, a same-origin content security policy and related headers, immutable caching for existing hashed assets, 404 for missing ones, `no-cache` for the shell and service worker. `HUB_STATIC_ROOT`/`HUB_API_UPSTREAM` overrides exist for the fixture only.
- Web: the service worker serves hashed assets cache-first and never stores an HTML answer under an asset name; Zod's compiled parsers are off so the policy is not tripped on load.
- Precache defect (live since CSS-only chunks appeared): the worker's precache list was taken before Vite removed the empty script chunk of a CSS-only import, so it named `/assets/Assistant-….js`, which is never written. The live server answers that path with the app shell, so installs still succeeded; with the new 404 for missing assets the worker would never have installed and offline would have stopped working. The list is now built after Vite's own bundle hooks, and the build fails if any listed file was not written.
- Ops: `provision.sh` installs the block as `/etc/personal-hub/hub.caddy` and never replaces an existing Caddyfile. `deploy/oracle-linux/test-edge.sh` runs the block under a real Caddy with synthetic content. `npm run edge:check` drives the built app in Chromium behind the same block (policy violations across every view, compression, worker cache, writes, export, offline shell). Neither is part of CI, which has no Caddy binary; both were run on the server's installed Caddy 2.11.7 on loopback without touching the live instance.
