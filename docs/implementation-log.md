## 2026-10-15 — Manual academic context in live owner asks (P7, development)

Implemented on `ai/academic-context` (not deployed). Live owner asks may now carry explicit, version-pinned manual academic work. `POST /api/v1/assistant/requests` accepts an optional `academic` array of `{ id, expectedVersion, expectedCourseVersion }` (≤20, unique ids). The prepare snapshot resolves each selection from `academic_work` joined to its active `courses` row and sends only an allowlisted projection — title, kind, date-only due date, estimated minutes, status and priority, with positional `w1…` refs. Notes, grades, class/instructor text, provider data and attachments never leave the server, and an unset deadline or effort stays `null` rather than zero or "none". The operation hash includes `academic` only when non-empty, so existing no-academic retries keep their hash and a device that sends nothing still replays.

Identity and version problems block the ask before any hold: missing, foreign or deleted work returns `404 NOT_FOUND`; a stale work or class version returns `409 VERSION_CONFLICT` ("Reload academic context."); an archived class returns `409 ACADEMIC_CLASS_ARCHIVED`; no request or reservation row is written. Labels are the deduped union of the work's retained `academic_labels`, the work sensitivity and the class sensitivity (≤3). A selection whose labels the destination may not receive is withheld and counted on the request (Restricted never sends; Personal only while **Allow Personal mail** is on) rather than failing the ask.

Each sent item is recorded in the sealed manifest as an `academic-work-v1` / `kind=academic-work` source carrying its labels and pinned `academicCourse={id,version}`, bound by a private digest. The final transmission guard re-projects every bound academic source and withholds the send as `context-changed` (no charge, hold released) if the work or class was edited, deleted, relabelled or otherwise changed between prepare and transmit, exactly like planner and mail sources. History eligibility re-verifies bound academic sources, so a follow-up keeps an unchanged academic turn and drops a changed one. Applied proposals inherit the academic labels and `bound-derived` origin through the existing boundary-2 lineage. Sent summaries are persisted on the turn (`ai_conversation_turns.academic`, migration 063) and survive conversation deletion; agent runs never carry academic sources. Migration 063 is append-only. The composer picker and withheld-item coverage UI are the next slice; grounded academic proposals (P8) follow later.
