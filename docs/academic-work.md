# Manual academic work

Backend implemented 2026-10-11; UI integration is pending. These owner-entered records fill missing academic deadlines, effort estimates, submission status and scores without claiming school-provider completeness. They remain separate from imported Canvas assignments, planner tasks/events and topic confidence. Explicit [linked task/study creation](academic-planning.md) and [reminder targets](academic-reminders.md) are implemented. Automatic matching, provider writes and mastery inference remain pending.

## Records and mutations

Shared contracts live in `packages/contracts/src/academic-work.ts`. `POST /api/v1/academic-work` uses `academicWorkWriteSchema`; `PUT /api/v1/academic-work/:id` uses `academicWorkUpdateSchema`. Both return `academicWorkResponseSchema` (`work`). Create requires an active owned `courseId`, title and operation ID. Records have kind assignment/exam/project/other, notes, nullable date-only `dueDate`, nullable integer `estimatedMinutes` (0-60000), priority 1-5, status planned/in_progress/submitted/cancelled, nullable grade, and sensitivity. Defaults are assignment, empty notes, unknown deadline/estimate, priority 3, planned, no grade and unlabeled. Inherited class labels may strengthen the effective label.

Updates are full record replacement with `operationId`/`expectedVersion`. Status and grade must be explicit on update to avoid accidentally clearing a score. Supply editable fields from the current record; do not send IDs, timestamps, provenance or captured label arrays. Other omitted fields take their input defaults, except omitted sensitivity preserves its current value. Class identity is immutable. Unknown/foreign records or unavailable classes return 404; stale versions return `VERSION_CONFLICT`. Editing a tombstone returns `ACADEMIC_WORK_DELETED`.

A grade is `{ earned, possible }` with nonnegative earned points and positive possible points, bounded to 1000000 and four decimal places; possible must be at least 0.0001. A score can exist only on submitted work. Zero earned points is a known score; null means no recorded score. Extra credit above possible points is accepted and flagged in summaries. Clearing a score or returning work to an open status requires an explicit null grade. Submission is owner-reported and does not claim a provider submission or measured learning progress.

`GET /api/v1/academic-work/:id` reads owned active records or tombstones. `DELETE /:id` and `POST /:id/restore` accept only `operationId`/`expectedVersion` and return the current work response. Deletion/restore advance versions without changing academic fields or IDs. Restore requires a currently active class; `ACADEMIC_CLASS_ARCHIVED` blocks restoration into an archived class, and `NOT_DELETED` means the item is already active. No purge/retention or offline mutations are implemented.

Every record has literal `provenance: owner-entered`, versions, timestamps, tombstones and complete `academicLabels`. This is record origin, not proof that manually pasted notes are approved AI input. Class relabeling appends captured labels and advances affected work versions, including tombstones and masked labels. Explicit later relabeling never discards captured history. Archived classes retain work history and summaries; creating/editing work in an archived class is blocked, while deleting historical work remains allowed. Class archival does not silently mark assignments submitted/cancelled or erase scores.

Reuse the exact endpoint/payload/operation ID after a lost response. A changed payload with that ID returns `OPERATION_CONFLICT`. Receipts are historical: a repeated delete can return its original tombstone after restoration, so reload current data before displaying a result as current. Label propagation can invalidate a pending restore version; reload and require deliberate review rather than automatically retrying with a new version.

## Browsing and class summaries

`GET /api/v1/academic-work` uses `academicWorkQuerySchema`: optional `courseId`, `status`, `before`, `deleted=true|false`, and limit 1-200 (default 50). Default reads include all statuses and only active records, including historical work in archived classes. `deleted=true` reads tombstones instead. `academicWorkListSchema` returns `work` and nullable `nextBefore`. Ordering is creation time descending then ID descending, with database microsecond precision retained. This browses records, not a complete revision timeline. Owned cursors remain usable after status/deletion changes. Preserve filters across pages; refresh/filter changes reset the cursor. Pages are not a frozen multi-request snapshot. Unknown/foreign cursors or requested classes return 404.

`GET /api/v1/courses/:id/work-summary?asOf=YYYY-MM-DD` uses `academicWorkSummarySchema`. The owner supplies the date in the intended local timezone; overdue means an open record with a deadline strictly before that date. Due-today work is not overdue. Deleted/cancelled records are excluded; submitted work is excluded from overdue/open effort totals. Active count includes submitted records.

The summary separates submitted count, submissions without recorded scores, recorded scores, missing deadlines/estimates and known estimated open minutes. `ungradedSubmittedCount` means no manually recorded score, not proof that the school has not graded the work; UI copy should say "Score unknown" or "No recorded score". Unknown estimates contribute no numeric minutes but remain visible as `missingEstimateCount`; explicit zero is known. Known estimates are the owner's full estimates, not measured remaining effort or minutes after subtracting study time. No topic confidence/progress is changed.

`recordedPointsPercent` is the ratio of summed manually recorded earned/possible points, or null when no scores exist. It can exceed 100 for extra credit. This is an unweighted recorded-points summary, not the institution's final class grade, gradebook completeness or mastery. Warnings always include `MANUAL_RECORDS_ONLY` and `NOT_FINAL_CLASS_GRADE`, with `EXTRA_CREDIT_PRESENT` when applicable. Class archival is explicit in `courseArchived`. More than 5000 active noncancelled records in a class blocks the summary with `ACADEMIC_WORK_TOO_LARGE` instead of returning truncated totals.

## Boundaries and validation

The cross-class [academic deadline agenda](academic-agenda.md) provides owned date-sorted open-work pages and full overdue/today/upcoming/undated totals for a chosen local horizon. It excludes archived classes, keeps missing estimates explicit and does not change source records or infer completion. UI integration remains pending.

Migration 026 adds records without changing applied migrations. Planner format-v1 export includes `records.academicWork` with scores, captured labels and tombstones; older exports default to an empty array. Existing export size limits apply. New endpoints are online-only and outside the task outbox/offline response-cache allowlist. The deterministic [study planner](study.md#academic-workload-signals-implemented-2026-10-11) uses open manual deadlines, priority and effort as class-ranking signals; owner weekly targets remain its budget, and scores are not used. Study time never changes estimates or submission state. Migrations 028/029 add explicit planner links and reminder targets. [Verified academic AI context](ai-academic-context.md) now supports explicit work/class versions and direct planner origins, excluding grades. Workload-plan and incomplete legacy history remain blocked. [Academic management](academic-management.md) adds guarded cross-class status browsing and atomic explicit selected changes with score protection; the original history/agenda routes remain available.
