# Verified AI context and synthetic text results

Implemented 2026-10-11. This adds context integrity binding, explicitly selected memory context and a bounded internal fake-adapter result flow. All public AI requests remain blocked with dispatchEnabled=false. No live provider, HTTP dispatch endpoint, worker, autonomous action or paid request is enabled.

## Exact context binding

Preflight and request assessment now include nullable contextManifest. An assembled manifest declares formatVersion=1, boundary=text-only, projection=owned-text-v1, owner-entered request sensitivity/character count, and each source's kind, owned ID, current version, complete resolved labels, attachmentDerived=false, memorySettingsVersion and projected character count. payloadCharacters counts the full JSON envelope. Blocked/unavailable routes and oversized envelopes have no assembled manifest.

The existing allowlisted task/event/class/topic/Canvas projections are preserved. Direct archived class/topic references are now rejected for text assembly; routing-only simulation preserves inspection of their retained labels. File-derived and incomplete academic provenance still block. Suggestions and sources cannot add attachments, screenshots, arbitrary source content or execution authority. Case variants of the same kind/UUID are duplicate context references.

Migration 038 adds a private context_hash to requests. New requests bind the exact serialized text envelope and safe manifest to the owner and request ID. This digest never appears in HTTP, mutation responses, export or logs. Prompt/source text is not persisted by this binding. Request creation and assessment share a repeatable snapshot and atomic receipt.

Admission re-resolves owned sources, versions, current labels and memory settings, assembles the same bounded projection and verifies the original binding before creating an attempt or hold. Changed text/labels without a root version change still return CONTEXT_CONFLICT. Legacy/unassembled requests have no binding; new admission returns CONTEXT_BINDING_REQUIRED and requires a deliberate newly assessed request. Existing claimed attempts retain metadata/recovery/no-resend behavior. Historical receipts never reconstruct forgotten memory or prompt text.

Both synthetic executors take a fresh read-only repeatable snapshot after committed admission and immediately before their one callback. They recheck context, routing/model, registry/policy/budget versions, current consent/version, pricing expiry and the owned uncertain hold. The hold counts once against the monthly limit; no second reservation is made. A source/settings/consent change blocks the callback and conservatively retains uncertainty. A change after the final snapshot cannot recall an already submitted payload; production stop/lease/session and provider reconciliation semantics remain pending.

## Explicit memory context

[Manual academic context](ai-academic-context.md) now supports explicit work/class version references and directly linked planner text through immutable provenance. Workload-derived study blocks and incomplete legacy history remain blocked.

AI context references add kind=memory with id, expectedVersion and required expectedMemorySettingsVersion. That extra field is rejected on other kinds. Both global settings and the individual memory must be enabled; the record must be owned, nonforgotten and source=owner-entered. Only kind/title/content/observedOn is projected. Complete owner label history follows the same provider intersection and no-fallback rules as other context.

Changing global settings invalidates pending references even if the owner disables then re-enables memory. Disable/forget/edit/version changes are checked again at admission and final revalidation. Forgotten memories remain text-free tombstones; no retrieval index, saved context copy, embedding, automatic extraction or automatic selection is created. UI memory selection remains pending. Current private integrity digests and safe admitted metadata remain; logical forgetting does not erase old backups or separate owner copies.

## Synthetic result flow

The internal executeSyntheticTextRequest requires NODE_ENV=test and a synthetic-text adapter. The callback receives a text envelope, a cloned safe context manifest, output allowance and AbortSignal; it receives no credentials. Default timeout is 30 seconds, with a bounded 1–30000 ms test override. Timeout aborts the signal, retains the uncertain hold and discards late results. An adapter ignoring abort cannot be forcibly stopped, but late completion never settles or resends the attempt.

Output is strictly answer (1–16000 characters) plus at most 20 suggestions, each containing only a source kind/UUID/version and a note (1–1000 characters). Every suggestion source must match admitted context. Extra action/tool fields, ungrounded references, oversized output and inconsistent synthetic byte-token counts are invalid. There are no task/calendar/email writes. Shape and grounding validation do not establish factual correctness or completed work.

The synthetic tokenizer counts UTF-8 bytes of the normalized output JSON and must fit maxOutputTokens. This is a fake transport contract, not a real tokenizer or invoice guarantee. Confirmed valid usage settles at immutable admitted prices even when output is invalid; malformed usage, transport errors or atomic accounting failure retain uncertainty. Existing accounting can record overruns independently of accepting output.

Validated output exists only in the immediate internal return with synthetic=true, retained=false, inherited routing labels and its context manifest. Migration 039 adds resultMetadata to attempt detail/export: synthetic=true, retained=false, status=validated/invalid, answerCharacters and suggestionCount. No answer, suggestion note or callback exception is stored or logged. Accounting, request status and result metadata commit atomically. An exact retry/restart returns current request metadata and result=null without repeating the callback. A completed request can have invalid output or unavailable temporary output; completion describes confirmed attempt accounting, not a delivered useful answer. Explicit per-request answer retention is now implemented separately in [provider setup](ai-provider-setup.md); conversation/prompt retention remains pending.

Final npm run check passed lint, strict types, formatting, production builds and 334 API/client tests; one optional standard PostgreSQL test was skipped. Sixteen new focused tests passed. The initial full run included the archived-routing preview regression; it was corrected and the clean full rerun passed.
