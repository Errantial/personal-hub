# Persistent agents, PR 2: UI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner creates, edits, runs and pauses agents inside the Assistant page, reads run turns in the pinned thread, and sets Tasks/Calendar authority in Settings › AI › Actions.

**Architecture:** The UI consumes the PR 1 endpoints only. Agents are a pinned group above Conversations in `AssistantView`. One `AgentDialog` handles create and edit. `AssistantTurnView` renders agent-triggered turns with a run line instead of a "You" bubble. A new `AIActionSettings` panel in `AIView` edits `/api/v1/ai/actions`.

**Tech Stack:** React 19, Vite, shared Zod contracts, Playwright + axe.

**Spec:** [docs/superpowers/specs/2026-10-14-persistent-agents-design.md](../specs/2026-10-14-persistent-agents-design.md). It builds on [PR 1 plan](2026-10-14-agents-1-backend.md), whose Task 1 and Task 6 Interfaces define every contract used here.

## Global Constraints

- Requires PR 1 merged: contracts `agentSchema`, `agentWriteSchema`, `agentUpdateSchema`, `agentTemplates`, `assistantTurnSchema.trigger/notAllowed`, conversation `agent`.
- Relative `/api` URLs; every write sends `operationId` and `expectedVersion` where the contract has one.
- Interface copy: concise labels; secondary explanations in `Help`; errors, pending and offline state stay visible (AGENTS.md).
- Targets at least `var(--target)`; works at 320 px; light and dark themes.
- E2E stubs agent endpoints or uses `AGENT_WORKER=off` servers; no real provider calls.
- Don't change the existing Apply/Undo flow for owner turns.
- Run `npm run check` and `npm run test:e2e`; update `docs/ui-agent-ledger.md` in the last task.

Copy fixed by the spec:
- Group heading "Agents"; button "New agent".
- States: "Next 7:00 AM" (local time from `nextRunAt`; weekday prefix when not today), "Paused", "Cap reached", "Failed".
- Run line: "Scheduled run · Tue 7:00 AM", or "Run now · Tue 7:00 AM" for manual runs.
- Settings options: "Automatic" / "Ask first" / "Off"; fixed line "Email: always asks first".
- Help: "These settings govern agent runs. Assistant answers always ask first."

## Review Focus

1. **Offline or session expired while saving the agent dialog** — expected: the dialog stays open with the draft and a visible error; nothing is lost. Test in Task 2.
2. **Agent deleted on another device while its thread is open** — expected: the thread stays readable (unpinned) and agent controls disappear after reload; no crash. Test in Task 3.
3. **Cap reached** — expected: the state reads "Cap reached", Run now is disabled with a reason, and raising the cap in the dialog resumes it. Test in Task 2.
4. **Schedule with six times, or a weekly schedule at 320 px** — expected: the time list wraps, remains operable by keyboard, and validates duplicates. Test in Task 2.
5. **Failed run** — expected: the turn shows the short reason and "Retry" (Run now) without opening details. Test in Task 3.

### Task 1: Agents group in the Assistant list

**Files:**

**Interfaces:**
- Consumes: `GET /api/v1/agents` → `agentsResponseSchema`; conversation list items with `agent`.
- Produces in `lib/agents.ts`:
  - `agentState(agent: Agent, now: Date): { label: string; tone: 'normal' | 'paused' | 'warning' }`. The label is "Cap reached" if `pauseReason`, else "Paused" if paused, else "Failed" if `lastRun?.outcome === 'failed'`, else "Next <time>" from `nextRunAt` in `agent.timeZone`.
  - `useAgentSeen(): { unread(agent): boolean; markSeen(agent): void }`. It uses localStorage key `hub:agents-seen` mapping agent id to the last seen `lastRun.id`.
- `AssistantView` renders `<nav aria-label="Agents">` above Conversations: the heading "Agents", a "New agent" button (opens `AgentDialog`, Task 2), and one link per agent (`route {name:'assistant', id: agent.conversationId}`) with the title, the state label and an unread dot (`aria-label="New run"`). Opening the thread calls `markSeen`. Conversations exclude items whose `agent` is non-null.

### Task 2: Agent dialog

**Files:**
- Create: `apps/web/src/components/AgentDialog.tsx`, `apps/web/src/components/AgentDialog.css`
- Modify: `apps/web/src/components/AssistantView.tsx` (open from "New agent" and from the thread header "Agent settings" button on pinned threads)
- Test: `tests/e2e/agents.spec.ts` (new)

**Interfaces:**
- Consumes:
  - `agentTemplates`
  - `POST /api/v1/agents` and `PUT /api/v1/agents/:id`
  - `POST /api/v1/agents/:id/run`
  - `POST /api/v1/responsibilities/:id/pause|resume`, using the existing responsibility mutation bodies
  - `DELETE /api/v1/responsibilities/:id`, behind `useConfirm` with title "Delete agent?" and the message "The conversation is kept."
- Produces: `AgentDialog({ agent?: Agent; onClose(changed: Agent | null): void })`.
  - Fields, in order:
    1. **Template.** A radio group (Daily plan, Mail triage, Deadline watch, Custom) shown only on create. Choosing one pre-fills title, goal, schedule and Use mail.
    2. **Title.**
    3. **Goal.** A textarea; the count is shown at 1800 or more of 2000 characters.
    4. **Schedule.** Daily or Weekly. Weekly adds a weekday select. The list of times uses `<input type="time">` with "Add time" (max 6) and "Remove" per row; duplicates show an error.
    5. **Use mail.** Help notes that labels still apply.
    6. **Monthly cap.** A dollar input converted to micros, range 0.10–50.00.
    7. **Spend this month.** Read-only, edit mode only.
  - Actions:
    - Save.
    - Cancel.
    - In edit mode: Pause/Resume, Run now (disabled with the visible reason "Paused" or "Cap reached" when not active) and Delete.
  - The time zone defaults to the browser zone and is editable through the existing `TimeZoneInput`.
  - Modal behavior follows `ConfirmDialog`: focus moves to the first field, Escape closes and focus returns to the opener.

- [ ] **Step 1: Failing E2E tests** (endpoints stubbed with `page.route`):
  - `creates an agent from a template`: choose Mail triage. The schedule shows four times (08:00, 12:00, 16:00, 20:00) and Use mail is on. Saving posts a body with `template 'mail-triage'` and `schedule.times` of length 4, and the dialog closes.
  - `keeps the draft when saving fails`: the POST returns 503 or the page is offline. The dialog stays open with the goal text intact and an error with `role="alert"`.
  - `cap reached`: the agent has `pauseReason 'cap-reached'`. Run now is disabled with the text "Cap reached"; raising the cap sends a PUT.
  - `six times and duplicates`: "Add time" is disabled at 6; a duplicate time shows an error and blocks Save; the layout has no horizontal scroll at 320 px.

### Task 3: Run turns in the agent thread

**Files:**
- Modify: `apps/web/src/components/AssistantTurn.tsx`, `apps/web/src/components/Assistant.css`
- Modify: `apps/web/src/components/AssistantView.tsx` (header for pinned threads; failed-run Retry)
- Test: `tests/e2e/agents.spec.ts`

**Interfaces:**
- Consumes: `AssistantTurn.trigger`, `AssistantTurn.notAllowed`, the item states written by the worker, and the conversation's `agent`.
- Produces:
  - **Run line.** When `turn.trigger === 'agent'`, the "You" bubble is replaced by `<p className="turn-run meta">`. The text is "Scheduled run · <weekday h:mm>" or "Run now · …" (from `turn.ask === 'Run now'`), using the request's `createdAt`.
  - **Applied items.** Items already `applied` when loaded show "Applied" and the existing Undo; no Apply button is shown for them.
  - **Details summary.** Adds "N not allowed by settings" when `notAllowed > 0`.
  - **Failed runs.** When the turn's request failed, the turn shows its reason (existing reason copy) and a "Retry" button that calls `POST /api/v1/agents/:id/run`.
  - **Pinned thread header.** Shows the agent state label and an "Agent settings" button. If `GET /agents` no longer contains the agent, both disappear and the thread renders as an ordinary conversation.
  - **Composer.** Stays available in agent threads, so owner replies steer later runs.

  - `failed run shows reason and Retry`.
  - `agent deleted elsewhere`: when the agents list no longer has the agent, the thread still renders and "Agent settings" is gone.
